# 1. PROJECT OBJECTIVE

Speech Arena is a multimodal speech-analysis platform designed to evaluate how effectively a person speaks.

It should work for:

- public speaking
- presentations
- interviews
- debates
- news anchoring
- storytelling
- speeches
- creators/influencers
- professional communication
- competitive speaking
- self-vs-self improvement
- 1v1 speaking battles
- team battles
- leaderboards
- Mimic Party

The system must analyze **how something was spoken**, not merely what was said.

The ML system must eventually detect:

- speaking too fast
- speaking too slowly
- irregular pacing
- excessive pauses
- missing pauses
- misplaced pauses
- filler words
- hesitation
- monotone delivery
- excessive pitch variation
- insufficient pitch variation
- low energy
- excessive energy
- weak emphasis
- incorrect emphasis
- unclear/mumbled speech
- inconsistent cadence
- delivery instability
- combinations of multiple flaws

The system must also identify:

> **WHERE in the recording the problem happened.**

For example:

```text
00:18.4 - 00:21.1
Speaking rate: +31% above reference
Problem: Too Fast
Severity: High
```

The final system should produce both:

1. numerical analysis
2. human-readable explanation

# 5. DATASET STRATEGY

The core of this project is NOT simply collecting random speech.

We need a **contrastive speech dataset**.

The strongest training example is:

```text
SAME CONTENT
       │
       ├── IDEAL DELIVERY
       │
       ├── TOO FAST
       │
       ├── TOO SLOW
       │
       ├── EXCESSIVE PAUSE
       │
       ├── MONOTONE
       │
       ├── LOW ENERGY
       │
       ├── EXCESSIVE ENERGY
       │
       ├── BAD EMPHASIS
       │
       └── MIXED FLAW
```

This allows the model to learn:

> "The words are the same, but the delivery changed."

That is the core scientific idea of Speech Arena.

# 20. SEVERITY MODEL

Build a separate regression head.

Input:

```text
audio embedding
+
acoustic features
+
reference comparison features
```

Output:

```text

```

Interpretation:

```text
0.00–0.20 = negligible
0.20–0.40 = mild
0.40–0.60 = moderate
0.60–0.80 = high
0.80–1.00 = severe
```

These thresholds must remain configurable.

# 23. TEMPORAL GROUNDING MODEL

The model must identify:

```text
WHEN did the flaw occur?
```

Do not only classify the entire recording.

Process audio in overlapping windows.

Example:

```text
window = 3 seconds
hop = 1 second
```

For every window:

```json
{
  "start": 18.0,
  "end": 21.0,
  "labels": {
    "too_fast": 0.92
  }
}
```

Then merge adjacent detections.

Example:

```text
18–21
19–22
20–23
21–24
```

becomes:

```text
18–24
```

Implement temporal smoothing and hysteresis to reduce noisy predictions.

# 25. MODEL TRAINING STRATEGY

Use staged training.

## STAGE 1

Freeze speech encoder.

Train:

```text
classifier head
severity head
```

## STAGE 2

Unfreeze the final few encoder layers.

Fine-tune with a much smaller learning rate.

## STAGE 3

Compare:

```text
frozen encoder
vs
partial fine-tuning
vs
full fine-tuning
```

Keep whichever generalizes best.

# 26. DATA SPLITTING

THIS IS CRITICAL.

Never randomly split segments from the same speaker across:

```text
train
validation
test
```

This causes speaker leakage.

Split by:

```text
speaker_id
```

at minimum.

Prefer:

```text
train speakers
validation speakers
test speakers
```

For synthetic variants, ALL variants generated from the same original recording must remain in the same split.

Otherwise the model will memorize the recording.
