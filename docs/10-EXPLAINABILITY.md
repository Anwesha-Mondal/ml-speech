# SPEECH ARENA: 10-EXPLAINABILITY

## 1. Introduction

Explainability is the core value proposition of Speech Arena. As dictated by Section 12 of the master prompt: *"The system must distinguish measurement from interpretation... Prefer 'speech rate increased' and 'this may reduce clarity' over unsupported psychological claims."*

The Explainability Module takes the raw mathematical `Flaw` objects generated by the Temporal Grounding module and translates them into structured, human-readable strings via a deterministic rules engine.

---

## 2. The Deterministic Translation Engine

We do **not** use an LLM (like GPT-4) to generate these explanations on the fly. 
Why? Because LLMs hallucinate, and the hackathon requires absolute *reproducibility* and *auditability*. If the math says the pitch variance dropped by 40%, the explanation must strictly reflect that exact statistic every single time.

### 2.1 The Template Architecture
We use a template-filling engine (like Jinja2 or a strict Python formatter) populated by the variables from the `Flaw` object.

**Template Schema:**
1.  **Fact Statement:** What exactly happened acoustically?
2.  **Data Point (Reference):** The baseline metric.
3.  **Data Point (Participant):** The user's metric.
4.  **Delta:** The normalized percentage difference.
5.  **Interpretation:** The mechanical consequence of the flaw.
6.  **Recommended Action:** How to fix it.

### 2.2 Template Example: Pacing Flaw

**JSON Input from Grounding Engine:**
```json
{
  "flaw_type": "PACING_TOO_FAST",
  "start_time": 21.4,
  "end_time": 25.8,
  "context": "We cannot dedicate we cannot consecrate",
  "reference_stat": 3.8,
  "participant_stat": 5.1,
  "normalized_delta": 0.34
}
```

**Template Engine (Python):**
```python
def explain_pacing_fast(flaw):
    return f"""[{format_time(flaw.start_time)}–{format_time(flaw.end_time)}] Your delivery deviated from the reference in speech rate.
Reference: {flaw.reference_stat} syllables/sec
Participant: {flaw.participant_stat} syllables/sec
Normalized deviation: +{flaw.normalized_delta * 100:.0f}%.
This occurred around [{flaw.context}].
Interpretation: the delivery became rushed and may reduce articulation clarity.
Action: slow down before the key phrase and restore the reference pause."""
```

## 3. Dictionary of Interpretations

To strictly adhere to the "Do not overclaim" rule, developers must only select interpretations from this approved, hardcoded dictionary.

### 3.1 Pacing & Pauses
*   **Fast:** "The delivery became rushed and may reduce articulation clarity."
*   **Slow:** "The delivery became sluggish and may lose listener momentum."
*   **Missing Pause:** "A structural pause was omitted, which removes the intended rhetorical emphasis from the preceding phrase."
*   **Misplaced Pause:** "A pause interrupted the grammatical flow of the sentence."

### 3.2 Pitch (F0)
*   **Monotone (Low Variance):** "Pitch variation decreased significantly, resulting in a monotone delivery that lacks dynamic engagement."
*   **Instability (High Variance):** "Pitch variation increased erratically, which may be perceived as a lack of vocal control."
*   **Up-talk (Rising terminal):** "Pitch rose at the end of a declarative sentence, which acoustically mimics a question." *(Note: Do not say "makes you sound unsure").*

### 3.3 Energy (RMS)
*   **Low Energy:** "Vocal volume dropped near the noise floor, risking unintelligibility."
*   **Abrupt Spike:** "Volume spiked abruptly outside the normal dynamic range."

## 4. Confidence Thresholds

The `Flaw` object includes a `confidence` float `[0.0, 1.0]`. 
*   If the alignment confidence for the transcript span is low (because of heavy background noise), the flaw confidence must also be lowered.
*   **UI Implementation:** The explanation card must conditionally render a warning if `confidence < 0.8`: 
    *   *System Note: High background noise detected in this segment; temporal measurements may be less accurate.*

This ensures total transparency with the end user and builds trust in the platform's scientific rigor.
